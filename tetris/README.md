# 俄罗斯方块（Tetris）—— 单机版 PC 小游戏

用 **C 语言** 编写、**raylib** 渲染的俄罗斯方块。最大的特色是：**七种方块的随机顺序由一个循环队列实现"7-bag 袋子系统"**——既能玩到现代方块手感（最多等 12 块一定能等到想要的形状），又顺便练了二维数组与循环队列。

---

## 一、怎么编译

1. 用 **Visual Studio 2022 或更高版本**打开解决方案：`Tetris.slnx`
2. 顶部工具栏选择配置 **Debug** + 平台 **x64**
3. 按 **F5**（编译并运行）或 **Ctrl+F5**（运行但不附加调试器）

**依赖会自动还原**，不需要手动配置：

- `raylib 5.5.0`：图形与音频库，通过 NuGet 包引用
- `Microsoft.googletest...1.8.1.8`：单元测试框架，随 Visual Studio 一起安装在本机（离线可用），包源登记在 `NuGet.config` 里

> 如果需要命令行编译，也可以直接用 MSBuild：
> `msbuild Tetris.slnx /t:Build /p:Configuration=Debug /p:Platform=x64`

---

## 二、怎么运行

编译成功后，可执行文件在：

```
x64\Debug\Tetris.exe
```

**注意**：`resources` 目录（中文字体）必须和 exe 放在一起——构建时已经配置了自动拷贝，直接双击 exe 即可运行。

最高分存档 `highscore.txt` 也会生成在这个目录下（第一次破纪录时才创建）。它是**纯文本三行数字**，依次是轻松 / 标准 / 挑战三档的最高分，你可以直接用记事本打开看，也可以手工改（改完重新打开游戏就会按你写的显示）。

---

## 三、怎么跑测试

测试是独立的工程 `TetrisTests`，用 gtest 编写，共 **138 条用例**。

两种跑法：

1. **在 VS 里**：菜单"测试 → 测试资源管理器"，点"全部运行"
2. **直接双击**：`x64\Debug\TetrisTests.exe`（它会打印每条用例的结果）

测试覆盖的内容：

| 用例组 | 数量 | 覆盖什么 |
|---|---|---|
| Phase 0 工程联通 | 2 | gtest 能跑、测试工程能链接游戏源码 |
| Phase 2 形状与旋转 | 20 | 七种形状定义、旋转方向正确性、出生位置 |
| Phase 4 循环队列与袋子 | 29 | 队列原有行为回归、7-bag 均匀性、预览一致性、Hold 规则 |
| Phase 5 棋盘与手感 | 28 | 碰撞、移动旋转、重力、锁定延迟、幽灵落点、连发 |
| Phase 6 消行与计分 | 32 | 消行规则、闪烁阶段、计分与连击、等级与难度 |
| Phase 7 最高分存档 | 15 | 读写、破纪录判定、各种损坏文件 |
| Phase 8 音效合成 | 12 | 音高、包络、峰值、琶音方向、确定性 |

## 四、操作方式

| 按键 | 功能 |
|---|---|
| ← → 或 A D | 左右移动（按住会连续移动） |
| ↑ 或 W 或 X | 顺时针旋转 |
| Z | 逆时针旋转 |
| ↓ 或 S | 软降（按住时下落快 7 倍） |
| 空格 | 硬降（瞬间落底并锁定） |
| C | 暂存（把当前方块存起来，换出上次存的） |
| ESC | 暂停 / 从暂停返回 |
| Enter / 空格 | 菜单确认 |
| ↑ ↓ 或 1 2 3 | 选择难度（轻松 / 标准 / 挑战） |

在标题画面按 Enter 开始；游戏中按 ESC 打开暂停菜单（继续 / 重开 / 回到标题）。

## 五、游戏规则要点

| 项目 | 设定 |
|---|---|
| 棋盘 | 10 列 × 20 行（另有 2 行隐藏缓冲） |
| 出块 | **7-bag**：七种方块打乱成"袋"，袋内每种恰好一个 |
| 预览 | 接下来 3 个 |
| 消行计分 | 1/2/3/4 行 = 100/300/500/800 × 当前等级 |
| 连击 | 连续多次落块都消行时，额外加 `50 × (连击数−1) × 等级` |
| 等级 | 每消 10 行升 1 级（等级不封顶，只有下落速度封顶） |
| 难度 | 轻松 5 级封顶（0.36 秒/格）、标准 8 级（0.13）、挑战 11 级（0.043） |
| 锁定延迟 | 落地后 0.5 秒内可微调；每次成功移动/旋转重置计时，最多重置 8 次 |
| 长按连发 | 按住 0.20 秒后开始，之后每 0.13 秒移动一格 |

## 六、代码架构

**最重要的一条设计原则：逻辑层不碰 raylib。**

```
┌─────────────────────────────────────────────────┐
│ 界面层（main.c / ui_*）                          │
│ 只做三件事：画面与输入、屏幕状态机、把时间喂给逻辑层 │
│ 不判断任何游戏规则                                │
└───────────────────────┬─────────────────────────┘
                        │ 单向调用
┌───────────────────────┴─────────────────────────┐
│ 游戏逻辑层（纯 C，禁止 include raylib）            │
│   game_logic  棋盘 / 碰撞 / 下落 / 锁定 / 消行 / 计分 │
│   tetromino   七种形状与旋转                      │
│   bag         7-bag 袋子系统（内含随机数与洗牌）    │
│   hold        暂存规则                            │
│   highscore   三档最高分存档                      │
│   input_repeat 按键长按连发                       │
│              └── circularqueue（循环队列，项目原有）│
└───────────────────────┬─────────────────────────┘
                        │ 被测
┌───────────────────────┴─────────────────────────┐
│ 测试工程 TetrisTests（gtest）                     │
│ 直接引用逻辑层的 .c 源码，不重复实现               │
└─────────────────────────────────────────────────┘
```

这样分层的好处很直接：**逻辑层可以脱离窗口做单元测试**（138 条用例全部不依赖图形界面），改配色、挪面板也绝不会碰到游戏规则。

### 文件清单

| 文件 | 层次 | 职责 |
|---|---|---|
| `main.c` | 界面 | 程序入口、屏幕状态机（标题/选难度/游戏中/暂停/结算）、输入分发 |
| `ui_config.h` | 界面配置 | 窗口尺寸、布局坐标、配色、字体路径、存档路径 |
| `ui_text.h` | 界面配置 | 界面上的全部文字（字形清单由这些文字自动拼出，不会漏字） |
| `ui_board.c/.h` | 界面 | 棋盘、网格、方块、幽灵块、消行闪烁 |
| `ui_panel.c/.h` | 界面 | 暂存、预览、统计、连击角落提示 |
| `ui_screens.c/.h` | 界面 | 标题画面（方块背景墙 + 卡片 + 动效）、难度选择、暂停、结算 |
| `audio.c/.h` | 界面 | 8 个音效的合成与播放（含连击升调） |
| `config.h` | 配置 | 逻辑层常量：棋盘尺寸、速度表、计分、手感参数 |
| `game_logic.c/.h` | 逻辑 | 棋盘、碰撞、移动旋转、重力、锁定、消行、计分、等级、难度 |
| `tetromino.c/.h` | 逻辑 | 七种形状的 4×4 数组、旋转、出生位置 |
| `bag.c/.h` | 逻辑 | 7-bag 袋子（随机数 + 洗牌 + 循环队列封装） |
| `hold.c/.h` | 逻辑 | 暂存槽与三条规则 |
| `highscore.c/.h` | 逻辑 | 三档最高分读写（任何异常都不崩溃） |
| `input_repeat.c/.h` | 逻辑 | 按键长按连发（DAS / ARR） |
| `circularqueue.c/.h` | 逻辑 | 循环队列（项目原有代码，本作只新增三个函数） |

## 七、可调参数都在哪

想改手感、配色、布局，基本都不必动逻辑代码：

| 想改什么 | 打开哪个文件 | 改哪个参数 |
|---|---|---|
| 下落速度、软降倍率、锁定延迟、连发速度 | `config.h` | `FALL_INTERVAL_LEVEL1`、`SOFT_DROP_MULTIPLIER`、`LOCK_DELAY_SECONDS`、`INPUT_DAS_SECONDS`、`INPUT_ARR_SECONDS` |
| 计分与连击 | `config.h` | `LINES_PER_LEVEL`、`COMBO_BONUS_BASE`、`CLEAR_FLASH_SECONDS` |
| 窗口大小、棋盘格子大小、面板位置 | `ui_config.h` | 一组布局常量与配色 |
| 音效时长、音高、音量 | `audio.c` | 顶部 `SPECS` 表 |
| 标题画面背景方块的下落速度与浓度 | `ui_screens.c` | `DrawFallingPieces` 里的 `speed` 与 `alpha` |

## 八、已知限制（有意为之，不是 bug）

1. **没有贴墙旋转补偿（踢墙）**：方块贴着墙或地面时旋转可能直接失败，这是简化旋转系统的固有行为。代价是偶尔会觉得"转不动"，好处是旋转规则简单、容易看懂。
2. **旋转时方块会在 4×4 盒子内位移**：同上，是简化旋转系统的必然结果。
3. **没有背景音乐**：只有 8 个音效，全部由代码合成（不依赖任何音频文件）。
4. **没有硬降奖励分**：规格有意去掉——硬降加分会让玩家为了分数去抢速度，与"放松解压"的定位冲突。

## 九、这个项目练到了什么

| 知识点 | 用在哪里 |
|---|---|
| **二维数组** | 棋盘是 `10 × 22` 的二维数组；七种方块各是一张 `4 × 4` 表；旋转就是整体转 90° |
| **循环队列** | 7-bag 袋子：出块 = 出队、补袋 = 整袋入队、预览 = 看队头第 N 个 |
| 环形下标与"牺牲一格"判空满 | `circularqueue.c` 的原有实现，本作新增了"看第 N 个""出队并取值" |
| 分层设计 | 逻辑层不依赖图形库，因此 138 条测试全都不需要窗口 |
| 单元测试 | 用 gtest 覆盖了形状、袋子、棋盘、计分、存档、音效合成 |
| 状态机 | 屏幕流转（标题→选难度→游戏中→暂停→结算）与消行闪烁阶段 |
| 音频合成 | 三角波 + 谐波 + 包络，现场算出 8 个音效，不引入音频文件 |

完整的需求、架构与分阶段验收记录见 [`project.md`](./project.md)。
