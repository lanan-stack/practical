## 1. 项目概述

### 1.1 我们要做什么

一个**单机版俄罗斯方块 PC 客户端小游戏**：

- 用 **C 语言**实现（源文件为 `.c`，头文件为 `.h`，不引入 C++ 特性）。
- 界面库使用 **raylib 5.5.0**（通过 NuGet 引入，与前作一致）。
- 复用并**原地扩展**项目中已有的**循环队列**（`circularqueue.h/.c`），用它实现
  **7-bag 袋子系统**与**预览功能**。

### 1.2 学习目标（这是项目的一半价值）

| 目标 | 在本项目中的落点 |
|---|---|
| 二维数组 | 棋盘是 `10 × 20` 的二维数组；七种方块各是一张 `4 × 4` 的二维数组；旋转 = 对二维数组做整体旋转 |
| 循环队列 | 袋子系统：袋子用循环队列承载，出块 = 出队，补袋 = 入队，预览 = 查看队头第 N 个 |
| 分层设计 | 游戏逻辑层是纯 C、不依赖 raylib，可以被独立测试；界面层只负责画和收键盘 |
| 单元测试 | 所有逻辑用 VS 的 **gtest** 写单元测试，测试用例先经用户审核再实现 |
| 详细注释 | 所有代码写详细中文注释，能当作学习材料阅读 |

### 1.3 游戏定位（决定一切参数的基调）

- **进程结构**：经典马拉松——无限下落，单局到死为止，以成绩为目标。
- **情绪目标**：**放松解压** + **爽快连续消除**。不是手忙脚乱的紧张竞技，也不是需要苦思的解谜。
- **由此推出的两条铁律**：
  1. 反馈要"**安静、不打扰**"：所有提示信息放在余光能看到的地方，不用大字居中、不用飘字打断视线。
  2. **三档难度全部给速度封顶**，游戏永远不会主动把玩家逼死；难度档只决定
     "速度最快到哪一步停下"和"你大概能玩多久"。

## 2. 玩法需求

### 2.1 核心循环

一块方块从棋盘上方落下 → 玩家移动 / 旋转 / 加速 → 落地锁定，并立即出现下一块 →
如果填满某一行则消掉该行，上方整体下移 → 分数增加 → 速度按难度档位变化 → 循环，
直到新方块出生位置被占用，本局结束。

### 2.2 三档难度（用户已确认）

开局时由玩家选择"轻松 / 标准 / 挑战"三档之一。三档**共用同一起步与升级节奏**，
只在**速度封顶**上分道扬镳：

- 起始速度：**1.0 秒/格**（即每秒下落 1 格）
- 升级节奏：**每消掉 10 行升 1 级**，等级从 1 开始
- 速度只与**当前等级**有关，与难度档无关；难度档只决定"最高升到几级"

**速度表（单位：秒/格，越小越快）**

| 等级 | 下落速度 | 轻松（封顶） | 标准（封顶） | 挑战（封顶） |
|---|---|---|---|---|
| 1 | 1.00 | 1.00 | 1.00 | 1.00 |
| 2 | 0.79 | 0.79 | 0.79 | 0.79 |
| 3 | 0.62 | 0.62 | 0.62 | 0.62 |
| 4 | 0.47 | 0.47 | 0.47 | 0.47 |
| 5 | 0.36 | **0.36（此后封顶）** | 0.36 | 0.36 |
| 6 | 0.26 | 0.36 | 0.26 | 0.26 |
| 7 | 0.19 | 0.36 | 0.19 | 0.19 |
| 8 | 0.13 | 0.36 | **0.13（此后封顶）** | 0.13 |
| 9 | 0.094 | 0.36 | 0.13 | 0.094 |
| 10 | 0.064 | 0.36 | 0.13 | 0.064 |
| 11 | 0.043 | 0.36 | 0.13 | **0.043（此后封顶）** |
| 12 及以上 | （不再使用） | 0.36 | 0.13 | 0.043 |

- **轻松档的语义**：速度封顶在 0.36 秒/格。游戏**不会主动把玩家逼死**，一局玩多久完全
  由玩家自己的失误决定——想停就停。
- **标准档的语义**：封顶在 0.13 秒/格（约每秒 7.7 格），够快、够刺激，但只要你手够稳，
  一样可以一直玩下去。
- **挑战档的语义**：封顶在 0.043 秒/格（约每秒 23 格），方块从出生到落底大约只要 0.9 秒，
  基本必须全程硬降来应对。它是"三档里最快的前半程 + 一个极其苛刻但**依然存在**的天花板"，
  而不是"设计成必死"。
- **预期单局时长**：轻松档由玩家决定（想停就停）；标准档 5～10 分钟；挑战档 5 分钟起步，
  技术越好可以拖得越久。

### 2.3 计分与连击（用户已确认）

**只按消行和连击计分。** 软降、硬降**不额外加分**（经典规则里硬降有加分，但那会鼓励
抢速度，与"放松解压"的定位冲突，故不采用）。

| 一次消掉的行数 | 基础分 |
|---|---|
| 1 行 | 100 |
| 2 行 | 300 |
| 3 行 | 500 |
| 4 行 | 800 |

**得分公式**

```
本次得分 = 基础分 × 当前等级 + 连击加成
连击加成 = 50 × (连击次数 − 1) × 当前等级   （连击次数 ≥ 2 时才有，否则为 0）
```

- **连击（COMBO）定义**：连续多次"方块落地锁定后都发生了消行"。中间只要有一次落块没消掉
  任何行，连击次数归零。
- **连击显示**：屏幕上的 `COMBO ×N` **安静地待在角落**（右侧信息栏底部），用小号文字显示。
  不许用大字居中、不许飘字、不许抖动，不能打断玩家视线。
- **消行的听觉反馈**：消 1 行、2 行、3 行、4 行音效各不相同，行数越多音越高、越饱满；
  连击时音调**一级一级往上走**（详见第 4 章）。

### 2.4 操作与手感（用户已确认）

**键盘映射**

| 按键 | 功能 |
|---|---|
| ← / A | 左移一格 |
| → / D | 右移一格 |
| ↓ / S | 软降（下落速度变为正常的 **7 倍**） |
| ↑ / W / X | 顺时针旋转 90° |
| Z | 逆时针旋转 90° |
| 空格 | 硬降（瞬间落到底并立即锁定） |
| C | Hold 暂存（规则见下） |
| ESC | 暂停 / 从暂停返回 |

> 软降调优记录：初版倍率是 10 倍（每格 0.1 秒），Phase 7 试玩时觉得偏快、不好精细对齐，
> 经用户确认放慢到 **7 倍**（每格约 0.14 秒）。相关测试已改为从常量推导时间，
> 以后再调倍率不会再让测试失真。

**长按连发（DAS / ARR）**

按住 ← 或 → 时：先等 **0.20 秒**，之后每 **0.13 秒**移动一格。
这个数值偏柔和可控，不会一按就滑到墙边，符合"放松"的定位。

> 调优记录：初版定的是 0.17 / 0.08，Phase 5 试玩时发现偏快（每秒 12.5 格，
> 横穿棋盘不到 0.8 秒），精细落点很难对齐，经用户确认放慢到 **0.20 / 0.13**
> （每秒约 7.7 格）。

**锁定延迟**

- 方块落地后不会立刻锁死，而是给 **0.5 秒**缓冲，期间还能左右微调或旋转。
- 每次移动或旋转会**重新计时**，但最多重置 **8 次**，防止玩家无限拖延不下落。

**幽灵块（落点影子）**

- 在方块正下方用半透明轮廓显示"如果现在硬降会落到哪里"。
- 颜色 = 当前方块颜色，透明度约 30%，只画轮廓和淡填充，不能比真方块更抢眼。

**Hold 暂存规则**

1. 暂存区为空时按 C：**当前方块存入暂存区**，然后**预览区的第一个方块立刻出场**。
   （此时不存在"换"这个动作）
2. 暂存区已有方块时按 C：**当前方块与暂存区方块互换**；被换出来的方块以
   **初始姿态**（旋转归零）出现在顶部出场位置，不继承之前的旋转状态。
3. **每个方块只能换一次**：换过之后，必须等这个方块落地锁定，才能再按 C。
   （否则玩家可以无限按 C，方块永不下落，一局就卡死了）
4. Hold 不消耗袋子里的方块、也不改变袋子顺序：换出来的方块直接成为当前方块，
   不回到队列末尾。

### 2.5 结束判定

- 新方块在**出生位置**出现时，如果该位置已经被已有方块占据 → 本局立即结束（标准顶出判定）。
- **棋盘采用"隐藏缓冲"模型（用户已确认，方案乙）**：
  - 逻辑棋盘为 **10 列 × 22 行**：其中**逻辑第 0～1 行是隐藏缓冲行**（不显示），
    **逻辑第 2～21 行对应屏幕上可见的 20 行**。
  - 行号换算：屏幕上第 r 行（r = 0～19，0 是最上面一行） = **逻辑第 r + 2 行**。
  - **出生位置**：方块的 4×4 盒子左上角放在 **逻辑行 1、逻辑列 3**。
    这样七种方块出生时都**恰好有一格落在可见区最上面一行**（不会"隐身"），
    同时逻辑第 0 行作为缓冲，留给旋转和顶出判定做余量。
  - 只有方块**完全进入可见区**之后，才按常规规则参与碰撞判定；
    停留在隐藏缓冲区的部分不参与碰撞。
- 顶出（游戏结束）：新方块在出生位置就与已锁定方块重叠 → 立即结束本局。

### 2.6 进程与界面流程（用户已确认）

```
标题画面（显示三档最高分）
      ↓ 选择难度
难度选择（轻松 / 标准 / 挑战）
      ↓
游戏中 ←────────────┐
      ↓ ESC          │
   暂停菜单 ──继续───┘
      ├── 重开 → 游戏中（同一难度）
      └── 退出 → 标题画面
      ↓ 顶出（游戏结束）
结算画面（本局分数 / 行数 / 等级 / 历史最高分 / 破纪录提示）
      ↓ 按键
标题画面
```

**操作方式**：全程可纯键盘完成（方向键选择 + Enter 确认）；鼠标点击属于可选增强，
不是必须项。

### 2.7 存档（用户已确认）

- **最高分按三个难度档分别记录**，互不干扰（轻松档的记录不会被挑战档比下去）。
- 存档写入 exe 同目录下的文本文件。
- **异常处理**（沿用前作贪吃蛇的严格做法）：文件不存在、打不开、是目录、内容为空、
  格式非法、数值越界、文件超大等情况，一律视为"无记录（0 分）"，**绝不崩溃、绝不误报**。
- 存档读写在**逻辑层**实现，可被单元测试覆盖（不依赖 raylib）。

## 4. 音效需求（用户已确认）

### 4.1 总体原则

- **有音效，无背景音乐**（不做 BGM）。
- 音效**全部由代码实时合成**（正弦波 / 三角波 + 少量高次谐波），
  **不引入任何外部音频素材文件**——不下载、不涉及版权、不受网络影响。
- 用户对该项提出的硬指标："**要好听点**"。因此：
  - 主音用正弦 / 三角波，只叠少量高次谐波，**不使用刺耳的方波主音**。
  - 每个音效都带**短促起音（约 5 毫秒）+ 平滑衰减尾（约 120～200 毫秒）**，
    不做"啪一下断掉"的干音。
  - 所有音效音量统一归一化，避免爆音、避免某个音效特别响。

### 4.2 音效清单

| 编号 | 触发时机 | 设计要求 |
|---|---|---|
| 1 | 左右移动 | 极短、极轻，几乎只有存在感，不能烦人 |
| 2 | 旋转 | 短促清脆 |
| 3 | 硬降 | 有"落地冲击感"，比锁定音更短更重 |
| 4 | 落地锁定 | 沉稳的一声 |
| 5 | 消 1 行 | 清亮 |
| 6 | 消 2 行 | 比 1 行高一档 |
| 7 | 消 3 行 | 再高一档 |
| 8 | 消 4 行 | 最饱满，用短琶音 / 和弦，是全曲最高光的时刻 |

### 4.3 连击升调规则

- 连击发生时，消行音的音高**一级一级往上升**。
- 升调**不按半音随意升高**，而是走**五声音阶**（do → re → mi → sol → la → 高八度 do），
  从根上避免出现不协和、刺耳的音程。
- 升到顶后循环回基础音，不无限升高（避免最后变成尖啸）。
- 音量**不随连击次数增加**，只升音高——保证不突兀。

## 5. 数据结构与算法需求

### 5.1 形状的二维数组表示（用户已确认）

- 每种形状统一用一张 **4 × 4 的二维数组**表示：`1` 表示这一格有方块，`0` 表示空。
- **旋转 = 把这张 4 × 4 表整体旋转 90°**（顺时针 / 逆时针各一种）。七种形状共用同一套
  旋转代码，不存在特例分支。
- 每种形状还需要记录：编号（0～6，供循环队列存储用）、颜色、在 4 × 4 盒子内的初始绘制位置。
- **不采用**"每种形状各存 4 个旋转状态的坐标列表"，因为那样就练不到二维数组了。

### 5.2 循环队列的原地扩展（用户已确认：方案 A）

**现状**：项目已有 `circularqueue.h/.c`，提供 创建 / 销毁 / 判满 / 判空 / 入队 /
出队（不返回值）/ 取队头 / 取队尾。数据存 `int`，通过牺牲一个存储单元来区分空与满。

**改造原则**

1. **原有函数一个字都不改**：名字、参数、行为全部保持原样，你原来写的练习代码照样能编译、
   语义不变。
2. **只新增**下面这几个函数来补上袋子系统需要的能力：

| 新增能力 | 作用 | 契约要求 |
|---|---|---|
| 查看第 N 个元素 | 从队头数起第 N 个（N=0 表示队头）。用于"预览接下来 3 个" | N 超出当前元素个数时视为非法，由调用方保证不越界 |
| 出队并取值 | 出队的同时把被移走的元素通过"输出参数"带回来 | **返回 bool 表示成功与否 + 输出参数带回数据**，不使用"魔法值"表示失败 |
| 查询当前元素个数 | 判断"是不是该补充新的一袋了" | 返回 0 到容量上限之间的整数 |

3. **关于"用 0 当空队列的哨兵值"的问题**（用户提问，已答复）：**不能解决问题，反而更糟**。
   `0` 在本项目里是合法数据（I 形方块的编号），改成 0 会真的与合法数据撞车。问题的本质是
   让一个返回值同时承担"数据"和"状态"两个职责——只要数据域覆盖该值必然冲突，与具体选哪个
   数字无关。现有 `-1` 之所以安全，只是因为数据域是 0～6，碰不到它，属于"隐式约定"。
   因此：**老函数保持 `-1` 约定不动，新增的取数函数一律使用 bool + 输出参数的显式契约。**

### 5.3 7-bag 袋子系统（本项目的核心算法）

**目标**：让七种方块以"每七块为一袋、每袋内七种各出现一次、顺序随机"的方式出现。
好处是：不会出现"连着十个 S 形"这种让人抓狂的情况。
**准确的不变式**：任意连续 **13** 个方块中，七种形状都至少出现一次；
等价的说法是"同一种方块两次出现之间最多隔 12 块"（这就是俗称的"最多等 12 块"）。
（推导见第 8 章 Phase 4 的 P4-23 说明。）

**规格**

1. 一"袋"= 把编号 0～6 的七种形状**洗牌**后得到的一个随机排列。
2. 袋子由一个**循环队列**承载，队列容量设计为**两袋的容量（14 个）**：
   - 开局：洗一袋（7 个）入队。
   - 每次取走队头出块后，若**队列内剩余元素 ≤ 预览数量（3）**，则再洗一整袋（7 个）压入队尾。
   - 这样任何时刻队列里都至少有 4 个待用方块，永远够显示 3 个预览，也永远不会空。
3. **出场顺序** = 队列的先进先出顺序；**预览** = 查看队头第 0、1、2 个元素。
4. 队列里存的是形状**编号**（0～6），不是坐标也不是整张 4 × 4 表。
5. 洗牌与随机数使用**可注入种子的自研随机数发生器**（沿用前作做法）：
   同一个种子必然产生同一串方块序列，测试才能复现和断言。

### 5.4 随机数

- 使用可注入种子的内部随机数（如前作的 xorshift 一类简易算法），**不要**直接用
  `rand()`：那样测试无法复现。
- 洗牌使用标准的 Fisher–Yates 洗牌（在二维/一维数组上原地打乱），保证每种排列等概率。

**需要注意的两处现状问题（Phase 0 处理）**

1. 现有 `circularqueue.c/.h` **尚未登记进 `Tetris.vcxproj`**（工程文件里的文件清单是空的），
   编译时不会参与构建，需要在 Phase 0 加进去。
2. 源码**编码不统一**。实测结果：

| 文件 | 实际编码 |
|---|---|
| `Tetris\Tetris\circularqueue.c`、`circularqueue.h` | GBK（无 BOM） |
| `Tetris\Tetris\Tetris.vcxproj` | UTF-8 无 BOM |
| `Tetris\Tetris\Tetris.vcxproj.filters` | UTF-8 带 BOM |
| `snake game\snake game\game_logic.c`（前作源码） | **UTF-8 带 BOM** |
| `snake game\README.md`（前作文档） | UTF-8 无 BOM |

   **约定（已定稿）**：全部源文件统一保存为 **UTF-8 带 BOM**，并在工程中开启
   `/utf-8` 编译选项；`circularqueue.c/.h` **只转换编码、不改任何逻辑**。

   **为什么这样约定，以及"中文注释会不会乱码"**：

| 情况 | 中文是否乱码 |
|---|---|
| 全 GBK 工程，不加任何编译选项 | 本机 VS 里正常；换环境、上传 git、用非中文系统打开会乱码 |
| 全 UTF-8 带 BOM | 正常。VS 与 MSVC 依据 BOM 自动识别为 UTF-8 |
| 全 UTF-8 带 BOM + `/utf-8` | 正常，且以后新建的"无 BOM 文件"也不会出错 —— **本项目采用** |
| UTF-8 **不带 BOM**，也不加 `/utf-8` | ❌ 编译器按 GBK 解读，注释与中文字符串全部变乱码（前作 README 就是这个情况） |
| 同一工程里 GBK 与 UTF-8 混用 | ❌ 必有一方乱码，这是最需要避免的情形 |

   结论：**UTF-8 本身不会造成乱码，"不带 BOM 又不告诉编译器"才会。**
   采用"UTF-8 带 BOM + `/utf-8`"属于双重保险，中文注释和界面中文都不会乱。
3. 界面要显示中文，必须**显式加载中文字形**：raylib 加载字体时如果不给字形清单，
   只带 95 个 ASCII 字形，中文会画成空白或方框。前作的做法是先把要用到的中文字符列成
   一份清单、转成字形编码数组后再加载字体，**本工程沿用同一做法**（Phase 0 就配好）。

**审核阶段确定的 4 处语义**（用户已同意）

1. **计分用"消行前"的等级**（基础分与连击加成都是）。
2. **连击的定义**：连续多次"落块后都消行"，第 n 次（n≥2）额外加 `50×(n−1)×等级`；
   一次消 4 行仍算 1 次连击；中间一次没消行则归零。

**实测中发现并修正的问题**（又是测试自己的错，实现没问题）

| 锁定延迟 | 方块落地后延迟一小段时间才锁死，期间还能调整 |
| 顶出 | 新方块出生位置已被占用，游戏结束 |
| 连击 / COMBO | 连续多次落块都发生消行 |
| 消行 | 一行被方块填满后消除，上方整体下移 |
